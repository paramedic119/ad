# これから作るもの（計画）

現状（実コードで確認）: パーツ 9 種 / レール 3 種 / ミッション 8 問 / JS 4,401 行 / GitHub Pages 公開済み。
保存（20 枠）と共有コード（JSON）は実装済み。自由制作モードは既定動作として既に存在する。

## 1. ミッションを 8 → 24 へ

### いまの問題

- 8 問は「新パーツを 1 つずつ紹介する」順で、難易度の段差が大きい（3 問目で立体、6 問目でキャノン）。
- クリア条件が 1 種類（`need` 個ゴール）しかない。実物のタスクカードの本質である「使えるパーツが決まっている」が再現できていない。
- 全部クリアすると、やり込む先がない。

### 4 つの島に分ける（各 6 問）

| 島 | テーマ | 内容 |
| --- | --- | --- |
| しょきゅう | つなぐ | まっすぐ / まがる / たかさ / わかれみち / クロス / おとしあな |
| ちゅうきゅう | とばす・うける | ジャンプ / うけざら / ボルテックス / キャノン / 合流 / 2 本立て |
| じょうきゅう | しばり | パーツ数 / 高さ / 6 こ全ゴール / タイム / 指定パーツ必須 / 立体交差 |
| チャンピオン | ふくごう | 上記条件を 2 つ以上組み合わせた 6 問 |

### クリア条件の型を増やす

`challenges.js` に `check` を足すだけ。既存 8 問はそのまま動く。

| 型 | 内容 | 工数 |
| --- | --- | --- |
| `need` | n 個ゴールへ | 実装済み |
| `maxParts` ★ | 使えるパーツ総数の上限（少ない手で解く） | 小 |
| `mustUse` ★ | 指定パーツを必ず使う | 小 |
| `timeLimit` | n 秒以内にゴール | 小 |
| `noTouch` | 禁止エリアを通らない | 中 |
| `order` | ゴールに入る順番（ボールに色が必要） | 中 |

★ の 2 つが実物のタスクカードに最も近い遊び。

### 強み

ブラウザなしで物理を回す検証の仕組みが動いており、8 問すべての「お手本」が在庫内で解けることを自動確認している。
新規ミッションも同じ仕組みで「必ず解ける」ことを保証できる。増設で一番効く資産。

### 進行の見せかた

いまは「クリア済み」フラグのみ → 星 3 つ（クリア / パーツ最小 / タイム）。同じ問題を 3 回遊ぶ理由になる。

### その先

ミッションエディタ。固定パーツを置き、在庫と条件を決めて保存する ＝ ほぼ既存の組み立て画面。
作ったミッションは既存の共有コードで配れる。

工数: 条件の型 = 小 / 16 問追加とお手本 = 中（1 問 30 分〜1 時間、お手本が最も重い）/ 星 3 つ = 中 / エディタ = 大

## 2. 自由制作モード（すでにある。見つからないだけ）

ミッションを開いていないときは常に自由制作。在庫は実物と同じ（みち 28、レール 9/6/3、ボール 6…）。
自動保存・20 枠保存・共有コードもある。しかし起動するといきなり盤面で、「これが自由制作モードだ」とはどこにも書いていない。
「じゆうに つくる」の文字はミッション中断ダイアログの中にしかない。

**新規開発ではなく「すでにあるものを表に出す」工事。**

1. **スタート画面** — 大きなボタン 3 つ（つづきから / じゆうに つくる / ちょうせん）。小
2. **在庫スイッチ** — 「セットどおり」⇄「むげん」。ミッションの `limits` の仕組みがそのまま使える。小
3. **盤の大きさ** — `boardRadius` はデータに入って保存もされているのに UI から変えられない。ちいさい(4)/ふつう(5)/おおきい(7)。小
4. **名前つき保存 ＋ サムネ** — いまは「コース 1」の自動連番。名前入力と 3D canvas から焼いた 1 枚。中
5. **URL 共有** — `serialize()` は数字の配列だけの小さな形なので base64url で `?c=…` に詰められる。JSON 手コピペは子どもには無理。中
6. **ギャラリー** — お手本コース 10 本ほど同梱し、開いて改造できるようにする。最も強い学習導線。中

## 3. 追加パーツ

### ブロッカー

**公式サイトにこの実行環境からアクセスできない。** `gravitrax-jp.com` / `gravitrax.com` / `ravensburger.org`
いずれも通信が拒否される（環境側の制限。迂回はしない）。「本家のホームページから」パーツ情報を取得できない。

進めかた:
- **A.** 対象拡張セットのページ内容を貼ってもらう（最も確実）
- **B.** セット名だけ指定してもらい、こちらの知識で組む（名称・寸法が不正確になる可能性あり、要確認）
- **C.** 情報に依存しない部分（下の仕分け）だけ先に進める

### 実装難易度による仕分け

パーツは「ボールが通るパス（`localPaths`）の集まり」として定義してあるため、
パスを 1 本足せば済むものと、そうでないものでコストが 10 倍違う。

**A 群 — いまの仕組みにそのまま乗る**（パーツ定義にパスを足すだけ、物理側の改造不要）
- トランポリン（反発の計算は実装済み）
- ループ（`walled` にすれば脱線しない）
- スパイラル / らせん（ボルテックスの親戚、降下パスは実装済み）
- トンネル（見た目のみ、通り道は `curve` と同じ）
- 長いレール / ブリッジ（`railXL` — span を伸ばすだけ）
- Y 字合流、角度違いのカーブ

→ 1 つあたり半日〜1 日。まとめて 小〜中。

**B 群 — 「動くパーツ」の仕組みが要る**（`sim.js` に状態を持つパーツの概念を追加）
- カタパルト / ハンマー / シーソー（ボールの重さで動く、可動部の当たり判定）
- ティップチューブ（一定数たまると倒れる、カウンタ付き）
- ターンテーブル（回転して行き先が変わる）
- スイッチ / フリップフロップ（既存の `splitter` がほぼこれ。手動切替と見た目の差のみ）

→ 土台に 2〜3 日 ＋ 1 つあたり 1〜2 日。中。

**C 群 — 前提が変わる / 範囲が大きい**（独立フェーズとして）
- リフト・エレベーター系 — 「重力だけ」という前提と衝突する。他のボールの重さで持ち上げる型なら B の応用で入る。
- 電子パーツ（POWER 系） — 音・光・トリガー。物理より演出寄りで範囲が広い。
- 水・磁石 — 別の物理が必要。レールベースのモデルには乗らない。

→ 大。

### 注意点

- GraviTrax / Ravensburger は商標。パーツが増え拡張セット名をそのまま使うほど「公式っぽさ」が増す。
  README にだけあるファンメイドの注記を、アプリ内（スタート画面の下）にも出す。
- 拡張を足すと「どのセットを再現しているのか」が曖昧になる。
  **「セットを選ぶ」という考え方**を先に入れておく（スターターのみ / ＋拡張 A / ぜんぶ、で在庫をセット単位で切り替える）。

## すすめる順番

1. スタート画面 ＋ 在庫スイッチ ＋ 盤の大きさ — 自由制作モードが見えるようになる。既存機能を出すだけで最も安く効く。
2. クリア条件の型を増やす ＋ ミッション 8 → 16 — 遊べる量が 2 倍。既存の自動検証がそのまま効く。
3. 名前つき保存 ＋ サムネ ＋ URL 共有 — ここで初めて「作品」になる。
4. **追加パーツ A 群** — ★ここに入る前に、公式情報の入手方法（A / B / C）を決める必要がある。
5. ミッション 16 → 24（新パーツを使う分）
6. 動くパーツの仕組み ＋ B 群
7. ミッションエディタ / ギャラリー

## 決めてほしいこと

1. **追加パーツの情報源** — ページを貼る（おすすめ）/ セット名だけ指定 / 一旦保留にして 1〜3 を先に進める
2. **自由制作の初期在庫** — 「セットどおり」を初期値にしてスイッチで解放（おすすめ。在庫の制約こそがこのおもちゃの面白さ）/ 最初から「むげん」
3. **着手点** — だん 1（おすすめ、最短で手応えが出る）/ だん 2（ミッションを増やすほうが嬉しい場合）
